📝 为什么要用 Hexo + GitHub Pages？

Hexo 是一个快速、简洁且高效的静态博客框架，基于 Node.js。搭配 GitHub Pages（免费托管服务），你可以：

  • 零成本拥有个人博客，无需购买服务器和域名
  • 完全控制博客的样式、内容和数据
  • 使用 Markdown 写作，专注于内容本身
  • 通过 Git 实现版本管理和多设备同步

🛠️ Hexo 常用命令速查

命令 作用
hexo init [文件夹] 初始化一个 Hexo 博客项目
hexo new "文章标题" 创建新文章（位于 source/_posts/）
hexo new page "页面名" 创建新页面（如 about，位于 source/页面名/）
hexo g 或 hexo generate 生成静态文件（存放到 public/ 目录）
hexo s 或 hexo server 本地预览（默认 http://localhost:4000）
hexo d 或 hexo deploy 部署到 GitHub Pages（需预先配置 _config.yml）
hexo clean 清除缓存和已生成的 public/ 文件夹
hexo g -d 生成并部署（常用组合）

📂 如何新建文章并推送到 GitHub？

1️⃣ 创建文章

2️⃣ 编写内容

使用 Markdown 语法编辑该文件，可以插入图片、代码块等。

3️⃣ 本地预览

bash
hexo clean && hexo g
hexo s
打开浏览器访问 http://localhost:4000 查看文章效果。

4️⃣ 部署到 GitHub

确保根目录的 _config.yml 中已配置好 deploy 信息（见下文），然后执行：

bash
hexo clean && hexo g -d
该命令会：

清空旧的生成文件

重新生成整个静态网站

将 public/ 目录下的所有文件推送到 GitHub 仓库的指定分支（通常是 master 或 main）

5️⃣ 等待几分钟，访问 https://你的用户名.github.io

🔧 部署配置示例（_config.yml）
yaml

部署部分

deploy:
type: git
repo: git@github.com:你的用户名/你的用户名.github.io.git
branch: master # 注意与 GitHub Pages 设置的分支一致
如果你使用的是 main 分支作为 Pages 分支，则 branch: main。

💡 进阶技巧：使用分支备份源码

为了避免本地电脑坏了导致源码丢失，可以把 Hexo 源码（_config.yml、themes/、source/、package.json 等）单独推送到 GitHub 的另一个分支（如 source）。

操作步骤：
bash

第一次：创建并切换分支

git checkout -b source

删除不需要的文件夹（这些是由 hexo g 生成的）

git rm -rf .deploy_git public

添加所有源码并提交

git add .
git commit -m “初始化源码备份”

推送到 GitHub

git push origin source

以后每次更新文章后

git add .
git commit -m “更新文章”
git push origin source
恢复环境（换电脑时）：

bash
git clone -b source git@github.com:你的用户名/你的用户名.github.io.git myblog
cd myblog
npm install
hexo g -d # 重新部署到 master

🖼️ 如何让文章支持本地图片？

在根目录 _config.yml 中设置 post_asset_folder: true

安装插件：npm install hexo-asset-image –save

创建文章后，会生成一个与文章同名的文件夹，把图片放进去

在 Markdown 中直接写 即可

（如果插件不兼容，可使用官方推荐的 标签）
